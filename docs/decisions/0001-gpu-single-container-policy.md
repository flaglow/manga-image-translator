# 전처리 GPU 컨테이너 단일(1대) 운영 원칙

## 배경

전처리(Pass A)와 로컬 LLM(vLLM, Hy-MT2)이 같은 물리 GPU(RTX 4090 24GB)를 공유하게
되면서 컨테이너 수가 자원·처리량 효율의 핵심 변수가 됐다. 2026-10-30 실측
(`docs/reports/2026-10-30-hymt2-glm-measurements.md` §4·§5)이 이 질문에 데이터를 줬다.

## 검토한 대안

| 대안 | 판정 | 근거 |
|---|---|---|
| GPU 1컨테이너 | **채택** | 22.5 p/분, VRAM 5.2GB, **4.3 p/분/GB** — VRAM 효율 최상 |
| GPU 3컨테이너 | 기각 | 34.5 p/분(+53%)이나 컨테이너당 효율 49%↓(2.2 p/분/GB) — GPU 경합 실측 |
| GPU 4~5컨테이너 | 불가 | vLLM 상시(≈4.8GB)와 함께 물리적으로 안 들어감(≈25.6GB>24GB) |

## 결정

**결론: 전처리 GPU 컨테이너는 1대(gpu1)를 기본 원칙으로 운영한다 — VRAM당 처리량이
최적이고 vLLM과의 공유 예산이 안정적이며, 증설은 처리량 +53%에 그쳐 비효율이다.**

## 결과와 후속

- GPU 목표 개수 기본값 1 (`.gpu_count=1`). 상한은 vLLM 감지 시 3(`GPU_MAX_WITH_LLM`)
  으로 유지 — 급한 대량 적체 시 일시적 2~3대 확장은 허용하되 상시 운영은 1대.
- vLLM 소형(hymt2-small)은 전처리와 분리된 고정 컨테이너로 상시 운영
  (`demo/doc/docker-compose-hymt2.yml`, GUI 자가치유 포함).
- 되돌리는 조건: 단일 GPU가 병목으로 배치 SLA를 어기는 정기적 증거가 쌓일 때
  3대 안에서 재평가(4대 이상은 vLLM 포기 없인 불가).
