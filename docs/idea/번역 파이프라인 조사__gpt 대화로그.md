나는 영어 -> 한국어 , 일본어 -> 한국어.

===
네, **기존 로그에서 완전 일치하는 원문은 재번역하지 않고 재사용하는 것**은 가장 기본적이고 효과적인 운영 팁입니다. 이는 번역 메모리(Translation Memory, TM)의 핵심 방식이며, 만화 대사처럼 “아니야!”, “그렇군…”, 감탄사, 반복되는 호칭이 많은 텍스트에서 특히 큰 절약이 됩니다. [docs.memoq](https://docs.memoq.com/12-2/en/Concepts/concepts-match-rates-from-translation-m.html)

## 캐시·TM 전략

### 완전 일치는 무조건 재사용
원문 대사가 기존 로그와 **문자 단위로 100% 동일**하면 이전 한국어 번역을 그대로 사용하세요. 이때 공백, 문장부호, 전각/반각, 줄바꿈까지 정규화한 뒤 비교해야 오탐을 줄일 수 있습니다. [docs.memoq](https://docs.memoq.com/current/en/Workspace/translation-results-list.html)

- 일본어: 전각 공백, `…`/`…`, `!`, `？`, 따옴표 통일  
- 영어: 대소문자, 스마트 쿼트(`’`/`'`), 하이픈, 줄바꿈 정규화  
- 숫자·기호·루비 문자는 원문 그대로 보존  

### 맥락 일치까지 저장
단순 100% 일치보다 더 좋은 단위는 **앞뒤 대사까지 같은 “맥락 일치(101% match)”**입니다. 예를 들어 “그래.”도 장면에 따라 “그래.”, “알았어.”, “그렇지.”가 될 수 있으므로, `(이전 대사, 현재 대사, 다음 대사, 화자)`를 키로 저장하면 재사용 품질이 올라갑니다. [docs.memoq](https://docs.memoq.com/12-2/en/Concepts/concepts-match-rates-from-translation-m.html)

### 유사 일치는 자동 적용 금지
90~99% 유사 문장은 “참고 번역”으로만 LLM에 넣고, 자동 채택하지 마세요. 한 글자 차이로 화자의 태도나 존칭이 달라질 수 있기 때문입니다. TM 업계에서도 fuzzy match는 검토·수정이 필요한 제안으로 다룹니다. [publikasi.dinus.ac](https://publikasi.dinus.ac.id/estructural/article/download/16014/6073/57570)

권장 임계값:

| 유사도 | 처리 |
|---|---|
| 100% | 자동 재사용 |
| 95~99% | LLM에 후보로 제공, 낮은 온도로 재번역 |
| 75~94% | 참고 예시로만 사용 |
| 75% 미만 | 일반 번역 요청 |

## 만화 대사 전용 팁

### 문장이 아니라 “발화” 단위로 처리
만화는 문장보다 **컷·페이지·화자·감정**이 맥락입니다. 따라서 다음을 함께 넘기세요.

- 화자 이름과 말투 프로필  
- 이전 컷 2~3개 대사  
- 장면 요약: 추격, 고백, 싸움, 일상 대화 등  
- 대상 독자와 톤: 소년물, 청년물, 로맨스, 코미디 등  
- 원문 줄바꿈과 말풍선 분할  

특히 일본어는 1인칭과 존칭만으로 인물 관계·권력 관계가 드러납니다. `わたし/僕/俺`, `さん/くん/ちゃん`, 존댓말→반말 전환은 단순 직역으로 놓치기 쉽습니다. [alibaba](https://www.alibaba.com/product-insights/ai-powered-manga-translation-tools-do-they-preserve-honorifics-and-cultural-tone-shifts.html)

### 캐릭터 스타일 시트를 만들어라
작품별로 아래를 한 장 분량으로 정의하세요.

```text
캐릭터: 타로
한국어 1인칭: 나
어투: 반말, 짧고 직설적, 싸울 때는 더 날카롭게
호칭: 진군 → "진", 선배 → "선배"
금지: 존댓말, 과도한 감탄사, 설명형 번역
```

이 시트를 시스템 프롬프트에 넣고, 대사마다 `speaker` 필드를 붙이면 캐릭터 일관성이 크게 향상됩니다.

### 의성어·의태어는 별도 처리
`ドキドキ`, `ザワザワ`, `バン!` 같은 표현은 문장 번역과 분리하세요. 한국 웹툰 관례에 맞는 후보군을 용어집으로 관리하고, 필요하면 LLM에게 2~3개 후보를 요청한 뒤 편집자가 고르는 방식이 좋습니다.

- `ドキドキ` → 두근두근 / 쿵쿵  
- `ザワザワ` → 웅성웅성 / 와글와글  
- `バン!` → 쾅! / 빵!  

### 말풍선 길이 제약을 넣어라
한국어가 원문보다 길어지면 편집 비용이 커집니다. 프롬프트에 다음을 명시하세요.

- 원문보다 20% 이상 길어지지 않게  
- 어조와 핵심 의미를 유지  
- 줄바꿈 수와 리듬 보존  
- 설명을 덧붙이지 않음  

## LLM 운영 팁

- **온도 0.1~0.3:** 창작 자유도보다 일관성이 중요합니다.  
- **짧은 입력, 충분한 맥락:** 대사 한 줄만 넣지 말고 앞뒤 발화와 화자 정보를 함께 주세요.  
- **JSON 입출력:** `source`, `speaker`, `translation`, `confidence`, `notes` 형태로 받으면 후처리가 쉬워집니다.  
- **출력 형식 강제:** “번역문만 출력”, “설명 금지”, “따옴표 금지”를 명시하세요.  
- **재시도 분리:** 1차는 소형 Q4 모델, 실패·저신뢰 대사만 Q5/Q6 또는 더 큰 모델로 재시도하세요.  
- **용어집 우선순위:** 인명, 기술, 세계관 용어는 모델 판단보다 고정 용어집을 우선시하세요.  
- **금지어·표현 규칙:** 특정 캐릭터가 쓰지 말아야 할 말투, 브랜드 표현, 연령 등급 관련 표현을 명시하세요.  

## 기존 로그 활용법

로그를 단순 캐시가 아니라 **품질 데이터**로 쓰는 것이 핵심입니다.

1. 원문-번역쌍을 정규화해 TM DB에 저장  
2. 사람이 수정한 번역은 “승인 번역”으로 표시  
3. LLM 초안과 최종 번역이 다른 경우 diff를 저장  
4. 자주 수정되는 패턴을 추출해 프롬프트·용어집에 반영  
5. 승인된 번역만 자동 재사용 허용  
6. 편집자가 거부한 자동 번역은 해당 원문-맥락 조합을 재학습/재검토 대상으로 표시  

특히 “LLM이 처음 낸 번역”과 “사람이 최종 확정한 번역”을 분리 저장하면, 나중에 어떤 유형의 대사에서 모델이 약한지 알 수 있습니다.

## 품질 검수 기준

자동 지표는 참조 번역이 있을 때만 의미가 크므로, 만화에서는 아래 규칙 기반 검사를 우선하세요.

- 화자 수와 말풍선 수 일치  
- 인명·호칭·용어집 일치  
- 존댓말/반말 규칙 준수  
- 의성어 누락 여부  
- 지나친 직역, 설명 추가, 어순 그대로 번역 여부  
- 말풍선 길이 초과 여부  
- 동일 캐릭터의 말투 일관성  

참조 번역이 있는 평가셋이라면 COMET을 중심 지표로, chrF/BLEU를 보조로 쓰는 방식이 일반적입니다. 다만 COMET도 담화·문체·문화적 뉘앙스를 완전히 대변하지는 못하므로, 만화는 사람 검수를 반드시 남겨두는 것이 좋습니다.

Hy-MT2-1.8B-FP8을 1차 번역기로 쓰면, **“빠르고 저렴한 대량 1차 번역 → 규칙으로 문제 대사만 걸러내기 → 필요한 대사만 상위 모델 재번역”** 구조가 가장 잘 맞습니다. Hy-MT2는 33개 언어 상호 번역과 다국어 지시 이행을 목표로 한 번역 특화 모델군이며, 1.8B는 경량 배포용 모델입니다. [ollama](https://ollama.com/RogerBen/HY-MT2-1.8B:latest)

## 2단 구조의 목적

이 설계의 핵심은 모든 대사를 큰 모델에 넣지 않는 것입니다.

1. **1차 번역:** Hy-MT2-1.8B-FP8이 대부분의 대사를 빠르게 번역  
2. **검증:** 규칙·통계·용어집으로 신뢰도가 낮은 대사만 표시  
3. **재번역:** 어려운 대사만 Hy-MT2-7B, Qwen 계열, 또는 외부 고성능 모델로 재처리  
4. **저장:** 사람이 승인한 결과를 TM에 반영해 다음부터 재사용  

만화 대사는 반복 표현이 많고 한 줄이 짧아서, 1.8B 모델이 잘 처리하는 비중이 높습니다. 반면 화자 전환, 존칭, 의성어, 암시적 뉘앙스가 있는 컷은 상위 모델 또는 사람 검수가 필요합니다.

## 역할 분담

| 단계 | 담당 | 처리 대상 | 목표 |
|---|---|---|---|
| 0단계 | TM/캐시 | 기존 로그와 완전 일치하는 원문 | 요청 생략, 비용 0 |
| 1단계 | Hy-MT2-1.8B-FP8 | 일반 대사, 짧은 감탄사, 반복 표현 | 속도·비용 |
| 2단계 | 규칙 검증기 | 전체 1차 결과 | 문제 대사 탐지 |
| 3단계 | Hy-MT2-7B 또는 더 큰 모델 | 저신뢰 대사 | 품질 보완 |
| 4단계 | 사람 편집자 | 고위험 대사 | 최종 품질 |

Hy-MT2-1.8B-FP8은 FP8 양자화 모델로, FP8은 일반적으로 메모리 요구량을 약 절반으로 줄이고 처리량을 높이면서 정확도 손실을 최소화하는 방식입니다. 다만 FP8 연산 가속은 Ada Lovelace·Hopper·Blackwell 등 특정 GPU에서 지원되며, 구형 GPU에서는 weight-only 방식으로 동작할 수 있습니다. [docs.vllm](https://docs.vllm.ai/en/stable/features/quantization/llm_compressor/fp8/)

## 1단계: Hy-MT2-1.8B-FP8

### 입력 단위
대사 한 줄만 넣지 말고, 가능하면 다음을 함께 넣으세요.

- 화자 ID 또는 캐릭터명  
- 직전 대사 1~2개  
- 장면 유형: 싸움, 일상, 고백, 긴장, 유머  
- 원문 언어와 목표 언어  
- 캐릭터 말투 규칙


## 2단계: 규칙 기반 검증

Hy-MT2-1.8B의 결과를 그대로 쓰지 말고, 아래 검사를 통과한 대사만 확정하세요.

### 자동 통과 조건
- 출력이 비어 있지 않음  
- 원문이 한국어로 번역되었는지 기본 판별  
- 인명·고유명사가 용어집과 일치  
- 코드, URL, 이모지, 숫자, 루비 문자가 보존됨  
- 원문 대비 길이 비율이 비정상적이지 않음  
- 동일 화자의 이전 대사와 말투가 크게 다르지 않음  
- 의성어가 사라지지 않음  
- 존댓말/반말 규칙을 어기지 않음  

### 재번역 대상
다음에 해당하면 상위 모델로 넘깁니다.

- 원문에 감정 표현이 강한데 번역이 지나치게 평이함  
- 존칭·반말이 화자 관계와 맞지 않음  
- 일본어 호칭이 사라지거나 잘못 처리됨  
- 의성어·의태어가 누락됨  
- 원문보다 지나치게 길거나 짧음  
- 같은 캐릭터의 직전 대사와 어투가 충돌함  
- 용어집 단어가 빠지거나 다르게 번역됨  
- 모델이 원문을 그대로 출력하거나 설명을 덧붙임  
- 사람이 최근 같은 패턴을 반복 수정한 유형  

## 3단계: 재번역 전략

재번역 모델은 한 단계 위 모델을 쓰는 것이 효율적입니다.

| 1차 모델 | 재번역 후보 | 추천 상황 |
|---|---|---|
| Hy-MT2-1.8B-FP8 | Hy-MT2-7B | 동일 계열 유지, 품질·속도 균형  [ollama](https://ollama.com/maternion/hy-mt2:7b-q4_K_M) |
| Hy-MT2-1.8B-FP8 | Qwen 7B/8B급 | 문체 지시, 긴 맥락, 자연스러운 한국어 산문 강화 |
| Hy-MT2-1.8B-FP8 | 외부 고성능 LLM | 표지 문구, 공식 홍보 대사, 고난도 유머 |

Hy-MT2 계열에는 1.8B 외에 7B와 30B-A3B MoE 모델이 있어, 같은 번역 특화 계열 안에서 단계적으로 올릴 수 있습니다. [github](https://github.com/Tencent-Hunyuan/Hy-MT2/blob/main/README_CN.md)

## 만화 특화 검증 규칙

### 존칭과 호칭
일본어→한국어에서는 다음을 특히 검사하세요.

- `さん`, `くん`, `ちゃん`, `先輩`, `先生`의 처리  
- 캐릭터 간 관계 변화: 존댓말→반말 전환  
- 1인칭 변화: `わたし`, `僕`, `俺`에 따른 말투 차이  
- 호칭이 사라져 관계가 모호해지는 경우  

일본어 경어와 호칭은 토큰화·전처리 과정에서 관계 정보가 손상되기 쉬워, 만화 번역 품질의 주요 변수로 꼽힙니다. 

### 의성어·의태어
`ドキドキ`, `ザワザワ`, `バン!`은 문장 번역과 분리하세요.

- 원문에 의성어가 있는데 번역에 없으면 경고  
- 장르별 후보군을 용어집으로 관리  
- 필요하면 1.8B에게 번역 1개, 상위 모델에게 후보 3개를 요청  
- 최종 선택은 편집자 또는 규칙 기반 선호 사전  

### 말풍선 길이
한국어가 원문보다 지나치게 길면 편집 비용이 커집니다.

- 경고 기준: 원문 글자 수 대비 약 130~150% 초과  
- 재번역 지시: “의미와 어조를 유지하되 더 짧고 자연스럽게”  
- 여전히 길면 사람 검수 대상  

## TM 활용

기존 로그는 다음 3종으로 나누세요.

| 유형 | 자동 재사용 | 예 |
|---|---|---|
| 승인 번역 | 가능 | 편집자가 최종 확정한 원문-번역쌍 |
| LLM 초안 | 불가 | 모델이 처음 낸 번역 |
| 수정 로그 | 학습용 | 초안과 최종본의 차이 |

**맥락 포함 exact match**를 만드는 것이 중요합니다. 단순히 `원문 → 번역`만 저장하지 말고, 아래를 키로 저장하세요.

```text
(원문, 화자, 이전 대사, 다음 대사, 장면 유형, 언어쌍)
```

그러면 “그래.”처럼 짧고 모호한 대사도 장면에 맞는 기존 번역을 재사용할 수 있습니다. TM은 원문 세그먼트와 대응 번역을 저장하고, 새 세그먼트와 비교해 exact 또는 fuzzy match를 제공하는 구조입니다. 

## 운영 기준

- **온도:** 0.1~0.3  
- **배치:** 말풍선 단위로 처리하되, 컷 단위 맥락을 함께 전달  
- **타임아웃:** 1.8B는 짧게, 재번역 모델은 넉넉하게  
- **로깅:** 원문, 프롬프트, 모델, 출력, 검증 결과, 최종 승인 여부  
- **샘플링:** 매일 일정 비율을 무작위 검수해 1.8B의 실패 패턴을 파악  
- **회귀 테스트:** 자주 틀리는 대사 유형을 고정 평가셋으로 만들어 모델·프롬프트 변경 시 재측정  
- **지표:** 참조 번역이 있으면 COMET을 중심으로, chrF/BLEU를 보조로 사용하세요.   

## 권장 흐름

```text
원문 정규화
 → TM exact match 조회
   ├─ 승인된 맥락 일치: 재사용
   └─ 미스: Hy-MT2-1.8B-FP8 1차 번역
 → 규칙 검증
   ├─ 통과: 확정
   └─ 실패: Hy-MT2-7B 또는 Qwen 7~8B 재번역
 → 재검증
   ├─ 통과: 확정
   └─ 여전히 위험: 사람 검수
 → 승인 결과 TM 저장
 → 수정 로그로 용어집·말투 규칙·검증 규칙 개선
```

이 구조에서 Hy-MT2-1.8B-FP8은 “처리량 담당”, 규칙 검증은 “품질 필터”, 7B급 재번역은 “난이도 대응”, 사람 검수는 “최종 보증” 역할입니다. 특히 만화는 반복 대사와 고정 캐릭터가 많아, TM과 캐릭터 스타일 시트를 먼저 정비하면 1.8B 모델의 실질 품질이 크게 올라갑니다. [ollama](https://ollama.com/RogerBen/HY-MT2-1.8B:latest)
